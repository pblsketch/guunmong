# js/game — 진행과 화면

## 맡는 것과 경계

app은 접근·재개·목차·설정·장부·깨어남을, stage는 게임 안의 그림·대화·초상을, world는 보행·대상·행동 표시를 맡는다. core의 G.world를 덮어쓰지 않는다. cutscene/wish/wake의 컷신·학습·지팡이, journal/interp/result의 정리·PNG 화면 등록을 유지한다. dream은 말판 없이 공통 도구를 초기화한다. event는 월드가 없는 옛 자료의 읽기 화면이며, hud는 꿈 보따리 단추를 현재 권한에 맞춰 갱신한다. board/prep/sim은 실행 HTML에서 제외하고 파일·기록은 보존한다.

저장·규칙·글 표기·소리는 core API로 처리한다. localStorage에 직접 쓰거나 새 저장 열쇠를 만들지 않는다. 장면 글과 지도·효과·승인 자산 메타는 data에서 읽는다. 실제 자료와 자산 교체는 이 폴더의 일반 수정 범위가 아니다.

## 연결 지점

- screens[kind](ctx,scene)의 Promise가 끝나면 app이 다음 진행을 연다. 결과는 계속 머문다. experience가 있는 scene/event/link는 screens.world로 표시하며 waking은 기존 화면 등록을 유지한다.
- on(scene/step/done/chapter/wake/reset/settings)과 toolbar를 유지한다. settings는 인자 없는 동기 알림이다. on은 해제 함수를 돌려주며 화면에 한정된 수신자는 취소 때 해제한다. 새 화면은 기존 열기 문을 우회하지 않는다.
- 월드는 구판 scene/chapter/between 훅과 꿈 점수 도구를 실행하지 않는다. 새 화면은 screens.world 또는 on으로 연결하며 육성·말판 훅을 되살리지 않는다.
- ctx.run은 화면 생성 시의 회차다. ctx.alive()는 회차·취소를, ctx.canAct()는 생존·현재 접근·writer를 검사한다. 모든 비동기 경계와 생성한 단추에서 다시 검사한다.
- ctx.canProceed()는 저장 완료된 현재 연출의 다음 표시를 허용한다. 난간 타격 뒤 현재 꿈 장면은 잠겨도 선방으로 이어 갈 수 있다. 새 장면 접근이나 지속 상태 쓰기 권한을 만들지는 않는다.
- ctx.canBrowse()는 현재 권한으로 마친 장면을 읽는 동작이다. reader의 마친 월드에서는 메모리 이동·대화만 허용하고 미완료 진행·답 입력·저장은 계속 막는다.
- ctx.step은 화면 표식과 쓰기 가능한 현재 진행만 저장한다. ctx.finishExperience는 필수 행동을 검사하고 done과 다음 pos를 core 전용 API로 한 번 확정한다. 성공한 마침을 app이 다시 계산하지 않는다. ctx.finishEvent는 구판 호출을 차단하며 성장 계산을 하지 않는다.
- ctx.next는 tray에 data-act=next 단추를 만들고 취소 때 false다. 화면 이탈 때 타이머·키 입력·관찰자·경로·대화 대기를 모두 정리한다.
- G.stage.mount/play는 공통 무대다. textOnly 옵션은 ctx.main에 대화·초상을 배치하며 월드에서는 필드 위의 임시 대화창을 쓴다. label/hideFace로 공개된 호칭만 내보내고 숨긴 정체의 얼굴을 제거한다. cutscene의 onPause와 setSpriteFrame은 기존 96px 지팡이 자세를 유지한다.

## 기록과 접근

- G.save.state는 깊게 동결된다. 직접 대입과 bare write를 쓰지 않는다. move/applyExperience/experienceHelp/finishExperience/commitWake 또는 transact(ctx.run,change,{readonly})로 변경하고 반환을 확인한다.
- 목차·주소·history·맵 출구·open·resume는 canOpen을 지난다. 깨어난 학생은 c3-awake 앞을 열 수 없다. 이동 가능한 공간이 미래 접근 권한을 만들지 않는다.
- 탭의 reader/acquiring/unavailable와 마친 장면의 ctx.readonly는 별개다. 다른 탭에서는 진행·답 입력·설정·초기화를 막는다. 저장 탭 안내와 명시적 권한 재요청을 제공한다.
- 직접 다시 보기는 위치·대사를 화면 메모리에서 재연하고 지속 상태를 쓰지 않는다. 현재 pos의 auto는 ctx.autoAdvance로 구분하며 안내 재생 후 다음 pos만 옮긴다. 최초 수행자·auto·부분 준비·옛 기록·장부를 보존한다.
- 깨어남 전 3장 재접속은 ctx.reenact로 취미궁부터 표시한다. 이미 저장한 행동을 메모리에서 재연하고 미완료 행동부터 저장한다. 마친 재연의 순차 진행은 다음 pos만 옮기며 직접 다시 보기와 구분한다.
- save.onChange의 storage/access/reset 알림에서 현재 화면과 대기를 폐기한다. pagehide는 즉시 취소하며 bfcache·권한 이전은 core가 최신 저장을 읽은 뒤 명시적으로 이어 한다. 옛 화면을 writer로 승격하지 않는다.
- 초기화는 확인 뒤 reset(run,{confirmed:true,cancel})로 화면·대기를 먼저 취소한다. 저장 실패 때 성공을 표시하지 않는다. 새 run에 옛 콜백이 쓰지 못한다.
- 설정 변경은 열린 도구와 단추 권한을 동기 갱신한다. 허용된 본문·입력은 보존하고 잠긴 장면은 설정판을 닫기 전 재개 위치로 옮긴다.

## 월드와 글

- 장소·현재 할 일 하나·가까운 행동·대상 목록·기본 메뉴만 표시한다. prep/grade/score HUD를 넣지 않는다. 인연은 개수·수치·보상·소원 입력이 아니며 꿈 동안 미색은 물음표다.
- 발을 보행 기준으로 삼고 승인 cell/anchor/directions 메타를 소비한다. 월드·말은 기기 픽셀 기준 정수 또는 역정수배이며 32px 걷기와 96px 지팡이를 혼동하지 않는다.
- 방향키/WASD, 터치 목적지와 대상 인접 이동, 가까운 상호작용 단추, 키보드 대상 목록 모두 core의 보행·거리·가시성·순서를 따른다. 도착만으로 사건을 마치지 않는다.
- 대화·설정·학습·화면 접기 중 이동을 멈춘다. 게임 밖의 방향키와 문서 스크롤을 가로채지 않는다. 닫을 때 포커스를 복구한다.
- 같은 scene의 map/spawn/appearance 전환은 저장된 행동을 이어 간다. 이전 지도 입력과 관찰자를 정리하고 안전 입구를 표시한다. 본문 표시 단계와 최초 수행 기록을 구분한다.
- 필드가 고정된 게임 화면을 채우며 모든 진행은 게임 안의 HUD·대화·활동·책·결과 창에서 이뤄진다. 외부 웹 문서처럼 지도 아래에 대화·목록·진행 단추를 늘어놓지 않는다. 긴 글은 게임 창 안의 페이지 또는 접근 가능한 스크롤로 읽고 큰 글자·키보드·터치에서도 잘리지 않아야 한다. 대화·입력·설정 동안 이동을 막고 창을 닫으면 필드 초점을 돌려준다. 대상 목록은 게임 안의 보조 메뉴로 같은 행동에 접근한다.
- 장부는 학습 두 활동의 첫 시도와 도움, 사건 상태·행동 근거를 보여 준다. app.wishes는 core의 원작 사실·물건 API를 사용하며 옛 성장 수치로 계산하지 않는다.

## 깨어남과 꿈 밖

- 지팡이 입력은 G.app.wake(ctx)를 동기 호출한다. 현재 staff 맥락·writer·run·접근을 검사하고 core.commitWake 성공 뒤에만 타격을 시작한다. 실패이면 들어 올린 자세를 지킨다. 일반 apply/finish로 staff를 완료하지 않는다.
- 들어 올린 자세는 0기준 2번에 멈추고 저장 뒤 3번 타격을 보인다. 입력 전 skip은 없고 타격 중 재접속은 선방부터다. 공간·옷·인물·물건·음악 대비를 쓰며 점수 폭발·점수→0 연출을 넣지 않는다.
- 지팡이 컷신은 같은 취미궁 필드에서 승인한 96px 원본 자세를 표시한다. 호승은 필드의 정지 전신도 같은 96px 원본의 0번 자세를 쓰며 보행 32px 시트로 축소하지 않는다. 타격 저장 실패는 올린 자세와 다시 누를 수 있는 단추·오류 안내를 유지한다. 새로 연 장면 자체의 진입 실패는 게임 안 오류 창으로 전환한다.
- 소원 찾기 a-wish와 맞대기 j-match의 첫 시도·도움·정오답은 유지한다. 인연 잇기만 미색을 공개하며 채점하지 않는다. 응답 전 해석·근거 잠금과 응답 뒤 수정 한 번을 보존한다.
- 결과 DOM과 900px PNG는 취미궁/선방의 승인 그림과 선택 근거를 같은 dreamTrace 모델로 표시한다. PNG는 미저장 이름을 먼저 저장한 뒤 클릭 시점 모델을 고정한다. 이름 저장 실패면 다운로드를 중단한다. 그림·글꼴·Blob 대기 뒤 ctx.alive와 최초 run을 다시 검사하고 화면 이탈·초기화에서는 다운로드를 취소한다.
- 맞대기의 지역 입력과 저장 결과를 분리하고 일부 오답 저장 실패의 재시도는 중복 기록하지 않는다. 해석 확인 뒤 선택은 동결하며 저장 실패 때에도 확정한 선택을 유지한다. 옛 완료·등급은 장부에서 이전 기록으로 표시한다.
- 결과·이름·PNG는 기기 안에서만 저장한다. 결과에서 조신 비교를 선택해 읽는 형식과 원작 결말을 유지한다.

## 검증

node tests/check-engine.mjs는 진행·readonly·auto·이관·회차·reader·HTTP/file 권한과 실제 HTTP bfcache를 검사한다. node tests/check-rpg.mjs는 실제 main/app을 사용해 부품 시험 world-opening/world-event, 대표 도입·깨어남, 앞부분과 후반의 행동·대화·전환·취소·가림·반응형·픽셀을 검사한다. 시험 배열이나 단추가 비면 실패한다. 이관용 저장 자료 주입은 별도 회귀이며 학생 완주 증거가 아니다.

index에는 월드 스타일·화면과 독립 dream이 등록되어 있고 본편 콘텐츠·학습·일지·해석·결과는 동결 상태용 저장 API에 연결되어 있다. check-chapters는 학습 실패 재시도·확정 잠금·장부·PNG의 모델과 취소를, check-content는 선생님용·진행 주입 없는 실제 본편 세 경로와 다운로드를 검사한다. 대표 검사만으로 본편 전체 통과를 주장하지 않는다. 전체는 생략 없는 node tests/run-all.mjs 종료 0과 원본 로그로 확인하며 캡처·로그는 tests/shots에 남긴다.
