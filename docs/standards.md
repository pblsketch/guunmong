# 규칙

## 완료 조건

- `tests/`에서 `node run-all.mjs`가 종료 0이어야 한다. assets·bgm·content·data·dream·chapters·engine·rights·sim 아홉 검사를 모두 실행한다. 실패·미실행·빈 단정을 통과로 세지 않는다.
- master 통합 전과 공개용 내보내기 전에 전체를 확인한다. 개별 검사나 음량 생략 결과는 완료 증거가 아니다. 전체 실행은 ONLY와 생략 인자를 거부하고 ffmpeg를 요구한다.
- 새 규칙에 맞춰 검사를 바꿀 때는 까닭이 되는 제품 변경과 함께 반영한다. 실패를 없애기 위해 검사 조건을 삭제하거나 실제 조작을 저장 주입으로 대체하지 않는다.
- 원본 출력은 tests/shots의 전체 실행 로그에 남긴다. 자동 검사, 실제 기기·수업 확인, 공개 주소 검증을 서로 구분한다.

## 실행과 모듈 경계

- 게임은 빌드 없는 HTML·CSS·순수 JavaScript다. 런타임에 npm 패키지·CDN·외부 글꼴·분석 도구를 넣지 않는다.
- file로 열어도 시작·저장·소리가 동작해야 한다. 데이터는 JSON fetch나 모듈 import가 아닌 script로 읽는다.
- script 순서는 core(util/save/data/audio/text/ui/activity/sim) → app → stage → board와 화면들 → main이다. G.dream을 초기 평가에서 쓰는 파일은 board 뒤에 둔다.
- core에서 app·dream·board·house를 호출하지 않는다. 화면은 screens·hook·on·toolbar에 연결한다. 새 화면 때문에 공통 진행을 우회하지 않는다.
- 비동기 대기 뒤 ctx.alive를 확인하고, 취소 신호에서 타이머·관찰자·애니메이션을 정리한다.

## 데이터와 표시 글

- 형식의 단일 기준은 js/data/README.md다. 새 필드를 먼저 명시하고 사용한다.
- data 파일은 GUUN에 순수 값을 대입한다. 함수·getter·G 호출을 넣지 않는다. 새 파일은 loader·형식 표·검사 목록을 함께 갱신한다.
- 실제 자료는 G.checkData 기본 검사로 경고 0이어야 한다. 시험 자료는 tests/fixtures에만 두고 명시적 fixture 검사만 사용한다. 실제 자료의 값으로 기준을 낮출 수 없다.
- 진행 id는 cut-josin, c장-이름, e01~e12-이름, l-이음, r-result 체계를 따른다. 활동 장부 id는 a-wish/j-match다. v2 배포 뒤 id·저장 형식 변경에는 기존 기록의 재개 경로를 함께 검증한다.
- 이야기 총량은 G.storyText 한 경로로 측정한다. 소원 장면의 서술을 빼거나 미노출 등급 문구를 제외하지 않는다. 근거 구절이 실제 이야기 줄에 있는지도 검사한다.
- 풀이·대사·설명은 새로 쓴다. 교과서 본문과 15자 이상 겹치는 문장, 금지된 출판사·교사 자료 사이트 이름을 추적 파일·이력·커밋 글에 넣지 않는다.
- 조사 두 꼴을 함께 쓰지 않는다. 바뀌는 앞말의 조사는 G.util.josa로 고른다. 얼굴 없는 인물은 say/호칭 링크로 그리지 않고, 표정은 등록된 값만 사용한다.
- 原文 표시는 대조된 orig에만 허용한다. 대조 전 자료에 orig를 넣으면 실패다. 대조 반영 시 근거·데이터·검사 기준을 같은 변경에서 고친다.

## 생성 자산과 화면

| 산출물 | 관리 방법 |
| --- | --- |
| bgm.js와 mp3 | make_bgm.py의 배정·출처에서 생성. bgm.js 수동 수정 금지 |
| 부분 글꼴과 OFL | build_fonts.py로 생성. 새 표시 문자를 넣은 코드·데이터와 함께 반영 |
| 기존 장면·말·집 등 | process_assets/process_sprites의 규격·팔레트 검사 유지 |
| 준비·지팡이·능력·자원 그림 | 승인 후보만 제품에 복사. manifest_sim96과 sprites 메타·검사 규격·해시 일치 |

- 그림은 32색 이하, 무손실 WebP이며 아이콘은 PNG도 사용한다. 준비·지팡이는 96px 셀, 기존 말은 32px 셀이다. 생성 원본·이전 후보는 assets/raw에 보존하고 커밋하지 않는다.
- 새 그림은 사용자에게 먼저 보여 승인받는다. 원본의 생성 프롬프트를 사후 가공 규격에 맞춰 허위로 바꾸지 않는다.
- 표시 배율은 기기 픽셀 기준 정수 또는 역정수이며 보간 확대를 하지 않는다. 그림·위치 좌표를 비율로 찌그러뜨리지 않는다. 시트도 메타 크기로 배율을 구한다.
- CSS 커스텀 변수는 style.setProperty로 등록한다. style 객체의 임의 키에 대입한 것만으로 등록됐다고 판단하지 않는다.
- 글은 그림 아래에서 온전히 펼치고 진행 단추를 그 뒤에 둔다. 긴 카드·큰 글자가 내부 스크롤이나 잘림을 만들지 않아야 한다. 중심 잘림으로 가려진 구슬은 전체 그림 보기에서 실제로 클릭 가능해야 한다. 검사에서 force 클릭으로 가림을 숨기지 않는다.
- 알림은 G.ui.toast만 사용하며 본문·진행 단추를 가리지 않는다. 흐린 글씨도 한지 바탕에서 명암비 4.5 이상, 출처 문구는 11px 이상이다.
- 진행은 tray의 data-act=next, 필수 선택은 data-must 표식을 유지한다. 호승 그림의 자세와 깨어남 저장 순간을 함께 검사한다.

## 기록과 검증

- 저장은 G.save.state와 write를 통해 수행한다. 새 localStorage 열쇠나 외부 기록 전송을 임의로 만들지 않는다.
- readonly 화면에서 장부·준비·능력·보상·물건·인연·구슬·해석을 바꾸지 않는다. 자동 기록의 순차 재생에서 다음 위치만 옮기는 경우와 직접 다시 보기를 구분한다.
- 모든 열기 경로는 canOpen을 거치며 깨어남 기록은 app.wake, 초기화는 확인 후 reset만 사용한다.
- 육성 조정은 모든 적중·윤목·출발 능력 조합을 검사한다. 준비 선택 직후와 등급 확정 직후 재접속, 자동 기록 재진입, readonly, 지팡이 전후, 해석 확정 뒤를 회귀 범위로 둔다.
- 화면의 상태 조건과 표시값은 같은 순간에 관찰한다. 선택 후 상태가 바뀐 요소를 예전 조건의 요소로 오판하지 않는다. 실제 잘못된 표시를 검출하는 음성 검사도 유지한다.

## 커밋과 외부 작업

커밋 글은 한국어로 쓰고 스테이지한 파일과 함께 권리 조건을 확인한다. 무시된 기획 자료·교과서·생성 원본·의존성·캡처를 강제로 추가하지 않는다. 작업 가지에서 검증하고 master 통합은 사용자 확인 뒤 수행한다.

GitHub 저장소 생성·업로드·Pages, 외부 양식 제출, 프로그램 설치, 교사 자료 사이트 접속은 할 때마다 먼저 확인받는다. 공개용 파일은 작업 이력 없이 내보내고 그 사본에서도 권리 검사를 실행한다.
