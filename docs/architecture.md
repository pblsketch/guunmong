# 시스템 구성

브라우저 안에서 실행되는 정적 HTML·CSS·JavaScript 게임이다. 게임 서버와 계정이 없으며 실행 중에는 같은 폴더의 파일만 읽는다. 내용은 `window.GUUN`, 실행 부품은 `G` 아래에 모인다. 데이터도 script로 읽어 파일로 여는 환경을 지원한다.

## 구성과 의존 방향

```text
순수 내용 데이터 → core의 읽기·검사·저장·육성 규칙 → app의 진행 제어 → 화면 모듈
                                                        ↓
                                               localStorage / 결과 PNG
```

| 부분 | 역할과 연결 |
| --- | --- |
| `js/data/` | 인물·장·말판·장면·소원·인연·집·일지·해석·노트·음원·동작 그림의 순수 데이터 12종 |
| `util`, `text`, `ui` | 요소·조사·정수배, 글 표기, 알림·시트·설정 공통 표시 |
| `data` | script를 읽고 누락과 데이터 경고를 수집. 실제 자료와 시험 자료의 검사 모드를 구분 |
| `sim` | DOM 없이 준비·등급·보상과 메모리 상태 전이를 계산 |
| `save` | 상태를 브라우저에 저장. 육성 계산을 호출하는 저장 래퍼와 활동 장부 제공 |
| `audio` | 로컬 녹음, 합성 대체 가락과 효과음. 배경음·효과음 설정 분리 |
| `activity` | 맞대기의 묶음 선택·확정과 도움 사다리 |
| `app` | 열기 문, 장 순서, 재개 위치, 깨어남, 목차·설정·장부와 확장 지점 |
| `stage` | 장면 그림 위 대사, 얼굴과 효과, 양소유 걷기. 다른 꿈 화면에 의존하지 않음 |
| `prep`, `event`, `hud` | 준비 두 턴, 사건·등급·단서, 꿈 점수와 소원·능력 표시 |
| `board`, `house`, `pearl`, `bag` | 말판과 공통 `G.dream`, 자동 장식, 구슬 탐색, 꿈 도구 |
| `cutscene`, `wish`, `wake` | 시간 순서 컷신, 소원 낱말 찾기, 난간 타격과 사라짐 |
| `journal`, `interp`, `result` | 맞대기·인연 잇기, 응답 전후 해석, 마지막 장과 PNG |
| `main` | 데이터 → 저장 → app 순서로 시작하고 첫 입력에서 소리를 해제 |

core는 app·말판·집을 호출하지 않는다. 화면은 app의 screens·hook·on·toolbar로 연결한다. 저장 모듈의 육성 래퍼는 시작 이후 호출되므로, 저장 파일보다 뒤에 로드되는 sim을 실행 시점에 참조한다.

`index.html`은 core(util → save → data → audio → text → ui → activity → sim), app, stage, 꿈 화면들, main 순서다. board가 `G.dream`을 만든 뒤 집·구슬·일지 등이 이를 사용한다. 준비·사건·컷신 등록은 모든 파일이 로드된 뒤 호출되는 함수를 연결한다.

## 한 판의 흐름

1. 데이터 12종을 읽거나 `fixture`에 지정된 시험 자료 하나를 읽는다. 누락은 `G.data.missing`, 형식 위반은 `G.data.problems`에 남는다. 자료가 없으면 시작 단추를 제공하지 않는다.
2. v2 저장을 읽고 주소 인자를 적용한다. 장면을 여는 모든 입구가 `canOpen`을 거친다. 허용되지 않은 요청은 현재 재개 위치 또는 처음 화면으로 돌아간다.
3. 새로 시작하면 확인 후 기록을 초기화하고 오프닝을 연다. 읽기 방식 선택은 없다.
4. app이 취소 가능한 화면 문맥을 만들고 장 안내와 화면 함수를 호출한다. 문맥의 신호가 취소되면 이전 화면의 대기·애니메이션·저장 작업이 끝난다.
5. 사건은 예고 → 준비 두 턴 → 대사 → 등급 → 단서 → 말판 이동으로 이어진다. 준비 선택은 즉시 저장하고, 결과 확정은 보상·마침·다음 위치를 연출보다 먼저 저장한다.
6. 이음 장면은 대사 뒤에 물건·능력 덤을 한 번만 적용한다. 말판이 같은 두 진행 단위 사이에는 추가로 걷지 않는다.
7. 선생님용 바로가기는 기록 없는 앞 사건에 보통 준비를 넣는다. 자동 기록을 순차 재생할 때는 기록을 보존하면서 진행 위치만 옮기며, 직접 다시 보기는 원래 위치로 복귀한다.
8. 지팡이 컷신은 올린 자세에서 입력을 기다린다. 난간 단추를 누르는 즉시 깨어남을 저장하고 내려치기 자세를 보인 뒤, 미리 만든 꿈 화면 조각을 흩뜨린다. 새로 열면 빈 선방부터 재개한다.
9. 꿈 일지, 응답 전후의 해석, 출가 컷신 뒤 결과 화면에 머문다. 학생이 누를 때 브라우저 캔버스로 PNG를 만든다.

## 저장과 소리

상태는 `guunmong-v2`의 JSON 한 덩이다. 시험 자료는 별도 열쇠를 쓰고 구판 v1은 읽거나 지우지 않는다. 같은 기기에서 여러 탭을 쓰면 나중 저장이 남는다. 원격 동기화는 없다.

http(s)에서는 로컬 mp3를 Web Audio로 재생하며 최근 곡의 디코딩 결과를 재사용한다. 파일로 열면 audio 요소를 사용하고 녹음을 읽을 수 없을 때 합성 가락으로 대체한다. 효과음은 브라우저 합성이다. 화면 접기는 두 소리 경로를 모두 멈춘다.

## 그림과 제작 도구

장면·얼굴·말판·집은 기존 도트 자산을 사용한다. 준비 네 동작과 지팡이는 96px 셀, 말판 말은 32px 셀, 능력·자원 아이콘은 32px다. 화면은 메타의 크기로 기기 픽셀 배율을 계산하며 그림 목록에 없는 동작은 기존 얼굴로 대체한다.

새 동작은 생성 원본 → `process_sim_assets.py`의 후보 가공 → 검토 → 제품 자산과 sprites 메타 순서로 들어온다. 생성 원본은 배포 파일이 아니다. 배경음은 `make_bgm.py`, 부분 글꼴은 `build_fonts.py`가 만든다. 제작·검사 도구는 게임 실행에 포함되지 않는다.

자동 검사는 설치된 Chrome과 로컬 임의 포트 서버를 사용한다. 아홉 검사와 ffmpeg 음량 측정의 출력이 전체 실행 로그에 남는다. 런타임에 기기 밖으로 나가는 기록은 없고, 학생이 직접 저장한 PNG만 결과 산출물로 남는다.
