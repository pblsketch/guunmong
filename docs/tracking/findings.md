# 풀지 못한 문제

현재 미해결은 아래 네 항목이다. 2026-10-05 코드 a1307bd의 전체 검사 10/10은 로컬 검증 결과이며 이 제약이나 최초 시간 초과의 원인까지 해결했다는 뜻은 아니다.

## 작업판 직접 진입 확인의 최초 시간 초과는 원인을 확정하지 못했다

- 조건과 증상: 게임 화면 통합 뒤 실제 root HTTP 주소의 새 브라우저 컨텍스트에서 시작하기를 클릭한 첫 확인이 이동 공간 표시를 30초 동안 기다리다 종료 1이었다. 이 첫 확인은 오류 시 권한·저장·DOM 관찰을 남기지 않아 이동 공간 부재와 비표시를 구분할 수 없다.
- 영향: 해당 자동화 한 번의 결과를 성공으로 세지 않으며, 그 결과만으로 제품 결함이나 원인을 확정할 수 없다.
- 현재 상태: 제품 코드 변경 없이 같은 주소의 직접 조작·대화 확인이 두 번 종료 0이었다. 이어 새 컨텍스트 다섯 번의 시작과 권한·회차·저장 알림 관찰도 모두 통과했다. tests/shots/game-ui-2026-10-05의 root-smoke.log, root-smoke-debug.log, root-smoke-confirm.log, start-probe.json에 원본을 보존했다.
- 지금 수정하지 않는 까닭: 재현과 최초 실패 시점 관찰이 부족하다. 원인을 추측해 진행·권한 코드를 바꾸지 않는다.
- 고칠 길: 같은 증상이 재현되면 시작 직전·직후의 저장 권한·회차·알림과 이동 공간·게임 화면의 실제 크기를 함께 기록해 진입 취소와 렌더링 문제를 구분한다.

## 본문 대조 경로가 고정되어 있다

- 조건과 증상: 다른 기기에 원래 저장소의 design/source/교과서_본문추출.txt가 없으면 check-rights 단독은 겹침 대조를 생략할 수 있다. check-data는 자료 부재를 실패로 처리하므로 현재 전체 run-all이 조용히 통과하는 문제는 막혔다.
- 영향: 별도로 실행한 권리 검사 출력만 보고 본문 대조까지 수행됐다고 오해할 수 있고, 다른 운영체제에서는 고정 경로로 전체 검사를 실행할 수 없다.
- 지금 해결하지 않은 까닭: 대조 자료는 비공개 저작물이라 배포에 포함할 수 없고, 이 개편의 확인은 자료가 있는 작업 기기에서 수행했다. 다른 환경의 대조 경로 입력과 운영 방식은 별도 변경이 필요하다.
- 가능한 길: 승인된 대조 파일의 경로를 환경 변수로 받아 없을 때 명시적으로 실패하도록 통일한다. 자료 생략을 완료 증거로 사용하지 않는다.

## 공개 주소를 대상으로 자동 점검을 돌릴 수 없다

- 증상: 모든 점검이 저장소 폴더를 자기 로컬 서버로 띄워 연다. 공개한 GitHub Pages 주소를 대상으로 학생 완주를 돌리는 옵션이 없다.
- 영향: 공개 뒤 경로(대소문자, 한글 파일 이름, Pages의 MIME 형식) 문제가 생겨도 자동으로 잡지 못한다.
- 지금 못 고치는 까닭: 점검 코드에 주소를 받는 옵션을 추가해야 하며, 이번 개편의 완료 확인은 로컬 구현을 대상으로 했다. 공개판 교체 후 검증 경로는 별도 작업이다.
- 길: check-content에 대상 주소를 받는 환경 변수(예: `BASE_URL`)를 더해 로컬 서버 대신 그 주소로 완주한다.

## 기존 장면·초상 그림 일부의 원본이 없다

- 증상: 가공 스크립트는 `assets/raw/<이름>.png`(생성 원본, git 제외)를 읽는데, 기존 장면·초상 등의 원본은 없고 화풍 시안만 남아 있다. 새 준비·지팡이·아이콘 원본은 assets/raw/sim-v2에 보존했으므로 이 문제에 해당하지 않는다.
- 영향: 기존 그림의 작은 어긋남(구경하는 승려의 머리, 봉래전 양소유의 관모 등)이나 색 줄이기 조정을 하려 해도 새로 생성해야 하고, 새 생성은 원래 그림과 얼굴·구도가 달라질 수 있다.
- 지금 못 고치는 까닭: 원본은 이미 없고, 새 생성은 그림을 사용자에게 먼저 보여 확인받아야 하는 일이다.
- 길: 고칠 그림을 정하면 같은 프롬프트로 다시 생성해 모아 보기로 확인받는다. 새로 생성한 원본은 무시된 원본 폴더에 보존하고 작업 폴더 정리 전에 안전한 보존 사본을 확인한다.

## 해결한 문제의 기록

아래는 당시 조건·영향과 해결 증거를 보존한 기록이며 현재 미해결 목록이 아니다.

### 최초 보따리와 구슬의 공개·근거 안내

- 조건과 증상: 최종 독립 검토에서 화음현의 첫 보따리가 동결된 seenFiction을 직접 바꾸다 열리지 않았다. 요연 구슬은 만남 전 정체·결과를 먼저 보여 주었고, 월드 구슬에는 원작 근거와 게임 설정 안내가 빠져 있었다.
- 수정: 설정 카드 기록은 포착한 run·readonly의 트랜잭션으로 저장하며 실패하면 기록을 보존하고 다음 열기에서 재시도한다. 구슬은 이미 읽은 서술 이후에 공개하고 기존 원작 근거 둘·게임 설정 여섯의 카드를 필드 위 대화창에 연결했다.
- 호환: 공개 시점을 늦추면서 옛 조기 수집 기록의 필수 행동까지 초기화하는 회귀를 발견했다. 실제 구슬 대상과 기존 수집 사실이 일치하는 이력은 보존하되 새 트랜잭션의 조기 수집은 거부한다.
- 재열기: 옛 seenFiction에 읽음이 남아 있어도 구슬 근거의 전체 설명은 표시한다. 표시 전용 showReal과 peek를 함께 사용해 읽기 이력은 변경하지 않는다.
- 근거: 최초 오류 원본은 tests/shots/independent-review-724194a, 보따리 RED/GREEN은 t10-fiction-red.log와 t10-fiction-green.log, 구슬과 호환 원본은 t10-pearl-worker 및 t10-legacy-pearl-red.log다. 네 사건의 호환과 읽음 이력 회귀를 포함한 구슬 집중 검사 20건, 보따리 회귀, 핵심 84묶음·대표 프로필 28개 단정이 전체 10/10 실행에서 종료 0이다. 누적 독립 검토도 지적 0건으로 승인됐다. 새 원본 전체 로그는 tests/shots/run-all-2026-10-05T08-08-47-668Z.log다.

### 교사 미리보기·자동 지팡이 재연·일반 저장의 깨어남 우회

- 조건과 증상: 독립 HTTP 검토에서 타격 전 교사 목차로 선방을 연 뒤 학생으로 바꾸면 awake:false 상태로 선방 행동을 학생 수행으로 저장할 수 있었다. 옛 auto staff를 재연하면 실제 commitWake 없이 타격 자세와 선방 pos로 넘어갔다. 공개 transact로 awake·선방 위치만 변경하는 경로도 허용됐다.
- 영향: 실제 지팡이 입력의 원자 저장과 교사 시연·학생 수행의 분리가 깨진다. 같은 run의 기존 awake:true를 잃은 사례는 아니다.
- 현재 상태: 해결하고 b6c56e7에서 작업 가지에 반영했다. 학생의 타격 전 선방 이후 접근을 차단하고 교사 미래 미리보기는 readonly·학생 pos 불변으로 전환했다. 옛 auto staff는 실제 입력을 기다리며 실제 타격의 commitWake만 완료·awake/최초 시각·선방 위치를 함께 확정한다. 공개 transact의 awake:false→true는 거부한다. 독립 최종 재검토의 findings는 빈 배열이며, 세 수정 회귀를 포함한 깨어남 21개·전체 RPG 88개와 호환 7개·핵심 84묶음·진행 20묶음이 종료 0이다. 통합 root HTTP에서 실제 취미궁·타격·같은 선방 조작도 확인했다.
- 고칠 길: 미래 목차 진입/OFF, 옛 auto 원문 이관, 일반 저장 최소 우회, 첫 저장 거부·같은 객체/원문 보존, reader·이전 run·힌트·다른 auto 보존을 검증한 뒤 실제 타격 성공에서만 3번 자세로 넘어간다.

### 이동 화면 완료 뒤 이전 입력이 다음 장소 좌표를 바꾼다

- 조건과 증상: 이동 화면 작업 사본에서 돌다리의 필수 행동을 마친 뒤 다음 장소 단추를 누르기 전에 방향키를 누르면, 화면은 돌다리지만 저장된 다음 선방 좌표가 바뀐다. 독립 검토의 실제 HTTP 조작으로 재현했다.
- 영향: 완료된 화면의 이동·대상 입력이 다음 장면 기록을 바꾸므로 표시와 저장의 장소가 어긋난다.
- 현재 상태: 해결했다. 완료 저장 뒤 이전 입력·경로를 중단했으며 실제 HTML의 방향키·터치·대상 목록 회귀와 독립 재검토가 통과했다. 원본 출력은 tests/shots/continuation-wired-rpg.log에 있다.
- 고칠 길: 완료된 화면에서는 다음 단추만 진행을 허용하고, 이전 월드의 지속 상태 변경을 거부한 뒤 같은 실제 입력으로 재검증한다.

### 장면 진입 저장 실패가 빈 화면으로 남는다

- 조건과 증상: 이동 화면 작업 사본에서 다음 장면 진입 때 저장소 쓰기가 실패하면 본문·진행 단추·오류 안내가 없는 화면이 남는다. 독립 검토에서 Storage.setItem 실패를 주입해 재현했다.
- 영향: 기록 저장에 실패한 상태를 학생에게 알리지 않으며 다시 시도할 길이 없어 진행이 막힌다.
- 현재 상태: 해결했다. 진입 트랜잭션과 화면 초기화의 실패를 오류·재시도로 연결했으며 기존 state/run 보존과 복구를 검증했다. 원본 출력은 tests/shots/continuation-wired-engine.log에 있다.
- 고칠 길: 기존 저장 상태를 보존하고 명시적인 오류와 재시도 경로를 제공한 뒤, 저장 실패와 복구를 같은 검증에서 확인한다.

### 저장 실패 화면의 홈·설정 단추가 반응하지 않는다

- 조건과 증상: 오류 화면에서 진행 ctx를 취소하면 홈·설정의 생존 검사까지 거부되어, 활성 표시된 두 단추를 눌러도 반응하지 않는다. 두 주요 수정의 독립 재검토에서 재현했다.
- 영향: 재시도 경로는 동작하지만 오류 화면에서 탐색·설정 사용이 막힌다.
- 현재 상태: 해결했다. 메뉴와 진행 입력 수명을 구분한 수정의 독립 재검토에서 blocking/nonblocking은 모두 0건이다. 실제 제품 HTML의 진행 검사 18묶음이 통과했으며 원본 출력은 tests/shots/continuation-menu-engine.log에 있다.
- 고칠 길: 진행 취소와 현재 화면의 메뉴 수명을 구분하고, 현재 회차·현재 화면에서만 홈·설정을 허용한 뒤 실제 클릭과 기록 보존을 검증한다.

### 승인 탑다운 자산의 가변 sprites 등록 검사

- 현재 상태: 해결했다. 가변 규격 등록 검사를 연결했고 이후 핵심 84묶음과 본편 콘텐츠·화면을 포함한 전체 10/10을 확인했다. 원본 전체 출력은 tests/shots/run-all-2026-10-05T06-22-48-990Z.log다. 아래는 자산 반영 당시의 실패 기록이다.
- 조건과 증상: 2026-10-04 탑다운 자산 반영 단계에서 승인 후보 8개와 승인 키트의 분리 칸 8개를 제품으로 반영한 뒤 `node tests/run-all.mjs`는 8/9 통과, 종료 1이다. 자산·음원·기존 학생 완주·데이터·꿈 도구·장별·엔진·권리 검사는 종료 0이다. 마지막 `check-sim.mjs`의 '등록 파일 존재·순서·공용 도구와 모듈 초기화'만 기존 sprites 12개 고정 목록 때문에 실패했다.

- 해결 방식: 기존 12개 계약을 그대로 검사하면서 `tools/manifest_topdown_approved.json`의 승인 항목 16개를 별도 메타 계약으로 검사했다. 당시 등록 열쇠 28개와 승인 메타의 일치·범위 검사도 유지했다. 이후 NPC·여도사 걷기 승인 항목과 실제 학생 월드 검사를 연결했다.
