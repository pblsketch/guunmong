# 풀지 못한 문제

## 본문 대조 경로가 고정되어 있다

- 조건과 증상: 다른 기기에 원래 저장소의 design/source/교과서_본문추출.txt가 없으면 check-rights 단독은 겹침 대조를 생략할 수 있다. check-data는 자료 부재를 실패로 처리하므로 현재 전체 run-all이 조용히 통과하는 문제는 막혔다.
- 영향: 별도로 실행한 권리 검사 출력만 보고 본문 대조까지 수행됐다고 오해할 수 있고, 다른 운영체제에서는 고정 경로로 전체 검사를 실행할 수 없다.
- 지금 해결하지 않은 까닭: 대조 자료는 비공개 저작물이라 배포에 포함할 수 없고, 이 개편의 확인은 자료가 있는 작업 기기에서 수행했다. 다른 환경의 대조 경로 입력과 운영 방식은 별도 변경이 필요하다.
- 가능한 길: 승인된 대조 파일의 경로를 환경 변수로 받아 없을 때 명시적으로 실패하도록 통일한다. 자료 생략을 완료 증거로 사용하지 않는다.

## 공개 주소를 대상으로 자동 점검을 돌릴 수 없다

- 증상: 모든 점검이 저장소 폴더를 자기 로컬 서버로 띄워 연다. 공개한 GitHub Pages 주소를 대상으로 학생 완주를 돌리는 옵션이 없다.
- 영향: 공개 뒤 경로(대소문자, 한글 파일 이름, Pages의 MIME 형식) 문제가 생겨도 자동으로 잡지 못한다.
- 지금 못 고치는 까닭: 점검 코드에 주소를 받는 옵션을 추가해야 하며, 이번 개편의 완료 확인은 로컬 구현을 대상으로 했다. 공개판 교체 후 검증 경로는 별도 작업이다.
- 길: check-content에 대상 주소를 받는 환경 변수(예: `BASE_URL`)를 더해 로컬 서버 대신 그 주소로 완주한다.

## 기존 장면·초상 그림 일부의 원본이 없다

- 증상: 가공 스크립트는 `assets/raw/<이름>.png`(생성 원본, git 제외)를 읽는데, 기존 장면·초상 등의 원본은 없고 화풍 시안만 남아 있다. 새 준비·지팡이·아이콘 원본은 assets/raw/sim-v2에 보존했으므로 이 문제에 해당하지 않는다.
- 영향: README '알려진 한계'의 작은 어긋남(구경하는 승려의 머리, 봉래전 양소유의 관모 등)이나 색 줄이기 조정을 하려 해도 새로 생성해야 하고, 새 생성은 원래 그림과 얼굴·구도가 달라질 수 있다.
- 지금 못 고치는 까닭: 원본은 이미 없고, 새 생성은 그림을 사용자에게 먼저 보여 확인받아야 하는 일이다.
- 길: 고칠 그림을 정하면 같은 프롬프트로 다시 생성해 모아 보기로 확인받는다. 새로 생성한 원본은 무시된 원본 폴더에 보존하고 작업 폴더 정리 전에 안전한 보존 사본을 확인한다.
