# 일하며 알게 된 것

## 글꼴

**새 글자가 다른 모양으로 보인다**
- 증상: 데이터나 화면 문구를 고친 뒤 몇 글자만 도트가 아니거나 명조가 아닌 글꼴(맑은 고딕, 바탕 등)로 보인다. 점검은 통과한다.
- 원인: `assets/fonts/`의 세 글꼴은 게임에 쓰인 글자만 남긴 부분 글꼴이다. 글꼴 파일이 없으면 404로 점검이 실패하지만, 파일 안에 글자 하나가 없는 것은 어느 점검도 보지 않는다. 브라우저는 조용히 CSS의 대체 글꼴로 내려간다.
- 대응: 글을 고칠 때마다 `python tools/build_fonts.py`를 돌리고 바뀐 woff2를 같은 커밋에 넣는다. 스크립트는 글자를 `js/**/*.js`, `index.html`, `manifest.webmanifest`에서만 모은다. CSS의 `content:` 글이나 README에 새 한글을 쓰면 모이지 않으므로, 화면에 보일 글은 JS나 데이터에 둔다.
- 확인: 스크립트가 글꼴마다 "글꼴에 없는 글자 N개"를 찍는다. 원본 글꼴에도 없는 글자가 생기면 그 글자를 바꾸거나 받아들인다.
- 학생이 결과 화면에 쓰는 이름은 미리 알 수 없으므로 부분 글꼴에 없는 글자가 대체 글꼴로 보이는 것이 정상이다(PNG도 마찬가지).

**'옛한글 글꼴'이라는 이름의 함정**
- CSS 주석과 파일 이름(`noto-serif-cjk-kr-old.woff2`, 글꼴 이름 GuunOld)은 옛한글 原文용처럼 보이지만, 실제로는 Noto Serif KR의 **한자**와 몇몇 문장부호만 담는다. 原文을 한문 회목·핵심 구절로 정했기 때문이다.
- 옛한글 자모(첫가끝·아래아)가 든 글을 原文으로 넣으면 `G.text`가 `old` 표시를 붙여 이 글꼴을 쓰게 하지만 자모가 없어 조합된 모양으로 나오지 않는다. 옛한글 原文을 쓰게 되면 옛한글 자모가 있는 원본 글꼴로 이 글꼴을 다시 만들어야 한다.

## 배경음

**`js/data/bgm.js`를 손으로 고친 것이 사라진다**
- 원인: `tools/make_bgm.py`는 곡 몇 개만 다시 만들 때도(`python tools/make_bgm.py calm lotus`) `bgm.js`를 통째로 다시 쓴다.
- 대응: 곡 배정, 악구, 합성 대체 곡(`synth`), 출처 문구는 스크립트의 `TRACKS`와 출처 문구 쪽을 고치고 다시 만든다.
- 다시 만들려면 원음 WAV(`tools/music_src/`, git 제외)와 ffmpeg가 이 기기에 있어야 한다. ffmpeg는 PATH 또는 `~/ffmpeg/bin/ffmpeg.exe`에서 찾는다.

**퉁소 곡이 실은 단소다**
- 국립국악원 「디지털 이음」 악구 목록에 퉁소가 없다(2026-10 확인). 난양공주의 달밤(`tungso`)과 취미궁(`chwimi`)은 같은 세로 대나무 관악기인 단소의 「청성곡」 악구로 만들었다. 출처 문구와 README에 "퉁소 대신 단소"가 있어야 하고, 내용 점검이 타이틀·설정의 출처 문구에서 이 표시를 본다. 퉁소 녹음을 구하기 전에는 이 문구를 지우지 않는다.

**음량 점검이 조용히 빠진다**
- `check-bgm.mjs`는 ffmpeg를 못 찾으면 음량(LUFS)·봉우리 재기를 건너뛰었다고 알리고 통과한다. 곡을 바꾼 뒤에는 ffmpeg가 있는 상태로 돌려 출력에 곡별 LUFS 표가 찍혔는지 본다(곡마다 -20 ±2, 봉우리 -0.5 dBTP 아래).

## 그림 만들기(Codex)

**Codex가 요청한 크기를 무시한다**
- 증상: `-Size 1536x1024`를 주어도 1672×941 같은 다른 크기·비율로 나온다.
- 대응: 가공 단계는 생성 크기를 믿지 않는다. `pixlib.center_crop()`으로 목표 비율의 가운데를 자르고 면적 평균으로 줄인 뒤 32색으로 줄인다. 그래서 프롬프트에 "중요한 것은 그림 높이의 가운데 80% 안에"를 넣고, 집 그림은 잘릴 띠의 위치를 계산해 그 안에만 그리게 한다. 새 프롬프트도 가장자리가 잘린다고 보고 쓴다.

**`gen.ps1`이 몇 분씩 멈춘다**
- 원인: 전역 `~/.codex` 설정의 플러그인·MCP를 불러오느라 시작이 멈춘다.
- 대응: `gen.ps1`은 그림마다 `%TEMP%\codex-img-guun-<이름>`을 `CODEX_HOME`으로 삼아 모델·승인·샌드박스 세 줄짜리 `config.toml`과 `auth.json` 복사본만 둔다. 이 방식을 바꾸지 않는다. 대신 생성이 끝나면 이 폴더들을 지운다(자격 증명 복사본이 남는다).
- 프롬프트는 영어(ASCII)로만 쓴다. 명령 줄에 그대로 넣어 넘기므로 한글이 섞이면 깨진다(스크립트가 `WARN`을 찍는다). Codex에게 프롬프트 파일을 읽게 하면 샌드박스가 막으므로 내용을 명령에 넣는 방식을 유지한다.
- 참조 그림 모드: `same`(같은 인물, 표정만), `style`(화풍만), `char`(옷·머리 모양만 따르고 도트로 다시 그림), `cast`(옷은 따르되 얼굴은 프롬프트대로), `scene`(설정 그림 속 인물 가운데 **이름을 댄 사람만** 그림). 장면에 다른 인물이 끼어들면 `make_prompts.py`의 `ref#n`으로 필요한 인물만 잘라 만든 참조 묶음을 쓴다.

**배경을 빼면 옷이 뚫린다(크로마 키)**
- 투명 배경 그림은 단색 배경으로 생성해 색으로 뺀다. 기본은 마젠타(#FF00FF)다. 보라·분홍 옷이 든 그림(적경홍 초상 시트, 선녀 시트 b, 승상 옷의 말 `horse_walk_sang`)은 초록(#00FF00)으로 생성한다. 버들 초록 옷의 진채봉이 든 그림은 초록 키를 쓰면 안 된다.
- 키는 두 곳에서 맞아야 한다: 프롬프트를 만드는 `make_prompts.py`(`KEY_GREEN`)와 가공하는 `process_assets.py`·`process_sprites.py`의 시트 표. 한쪽만 바꾸면 배경이 남거나 옷이 사라진다.

**구슬처럼 아주 작은 그림**
- 16px 안팎의 구슬 세 장은 생성 그림을 줄이면 뭉개지므로 `process_assets.py`의 `beads()`가 직접 찍는다. 아주 작은 그림은 생성하지 말고 코드로 찍는다.

**말 스프라이트**
- 시트는 32×32 칸 6열×4줄(서 있기 2, 오른쪽 걷기 4, 뛰기 6, 위로 걷기 4), 발밑 기준점은 칸의 (16, 30)이다. 모든 프레임을 서 있기 첫 프레임의 키(28px)로 같은 배율로 줄이고 발을 기준점에 맞추어야 걸을 때 튀지 않는다. 가공 중 칸을 벗어난 프레임은 잘렸다고 찍힌다.

## 화면

**조사가 '을(를)'로 찍힌다**
- 앞말이 데이터에서 오는 문장은 `G.util.josa(낱말, '을/를')`로 조사를 고른다. 이 함수는 마지막 한글 글자의 받침을 보고, 닫는 문장부호·따옴표·괄호(괄호 안 한자 포함)는 건너뛰고, 숫자는 읽는 소리로 보며, ㄹ 받침 뒤에는 '으로'가 아니라 '로'를 고른다. 해석 글처럼 「」로 감싼 말에 붙일 때는 「」를 포함한 글을 넘긴다.

**알림이 글이나 단추를 가린다**
- `G.ui.toast()`는 위 막대(`.topbar`)의 빈 곳(장면 이름 글자 끝과 오른쪽 단추 사이)에 작은 띠로 뜨고, 자리가 모자라면(휴대폰) 위 막대 전체를 덮었다가 누르면 닫힌다. 위 막대가 없는 화면에서는 화면 맨 위에 뜬다. 알림을 본문 위나 아래 판 근처에 새로 띄우면 내용 점검의 알림 위치 재기가 실패한다.

**흐린 글씨 명암비**
- `--ink-3: #6a5a47`은 한지 바탕(`--paper`)에서 명암비 4.5를 넘기려고 고른 값이다. 이보다 밝은 회갈색이나 투명도를 쓴 글씨는 내용 점검의 명암비 재기에서 걸린다. 그림이 바탕인 곳은 재지 않는다.

**좁은 휴대폰에서 장면 그림이 화면보다 작다**
- 도트 그림은 기기 픽셀 기준 정수배(또는 1/정수배)로만 크기를 정한다. 480×270 장면이 화면 폭보다 넓으면 1/2배로 줄어 폭보다 작게 보인다. 이것은 정상이며, 비율로 늘려 맞추면 정수배 점검이 실패하고 도트가 뭉갠다.

**뒤로 가기로 깨어나기 전 화면이 되살아난다**
- 브라우저가 예전 화면을 캐시(bfcache)에서 그대로 되살리면 스크립트가 다시 돌지 않는다. `app.boot()`가 `pageshow`의 `persisted`에서 저장소를 다시 읽고 지금 화면을 다시 판단한다. 새 화면 모듈이 자기 상태를 따로 들고 있다면 같은 때에 다시 그려야 한다.

## 저장

**저장 모양을 바꿀 때**
- `G.save.load()`는 `Object.assign(fresh(), 저장된 것)`이라 새 맨 위 열쇠는 기본값을 받지만, 안쪽 객체(`journal`, `interp`, `ledger`…)는 섞지 않고 옛 것을 그대로 쓴다. 안쪽 모양을 바꾸면 이미 진행 중인 학생 기기의 옛 모양을 읽어도 깨지지 않게 방어 코드를 둔다(`journal.js`·`interp.js`의 `jst()`·`ist()`처럼). 저장 안의 `v: 1`을 읽는 변환 코드는 아직 없다.
- 장면 id를 바꾸면 그 id를 가리키던 `pos`·`done`이 허공을 가리킨다. `pos`를 못 찾으면 이어 하기가 첫 장면으로 간다.

**다시 연 장면이 기록을 바꾼다**
- 새 걸음이나 화면을 만들 때 `ctx.readonly`(마친 장면 다시 열기)를 보지 않고 상태에 쓰면, 학생이 목차로 마친 장면을 다시 열기만 해도 장부·집·구슬이 바뀐다. 쓰기 전에 언제나 `if (!ctx.readonly)`를 건다. 꿈 일지·해석처럼 한 번 정한 뒤 잠기는 화면은 `final`·`heard` 같은 자기 표시도 함께 본다.

**3장 이어 하기**
- 깨어나기 전에 3장에서 끄면 3장 처음부터 다시 하므로 `app.resume()`이 3장 장면의 `done`을 지운다. 3장 장면에 새 기록을 더하면 이 되감기에서 어떻게 될지(장부처럼 첫 기록을 지킬지)를 정해야 한다.

## 점검

**작업 가지 폴더(worktree)에서 점검이 시작도 못 한다**
- 증상: `node tests/check-*.mjs`가 `Cannot find package 'playwright'`로 끝난다.
- 원인: `tests/node_modules`는 git이 빼므로 새 worktree에는 없다.
- 대응: 원래 폴더의 것을 Windows 연결점(junction)으로 잇는다. 관리자 권한이 필요 없다.
  `cmd /c mklink /J tests\node_modules "E:\github\고전 문학 게임\구운몽\tests\node_modules"` (worktree 맨 위에서)
- 권리 점검과 내용 점검은 교과서 본문 추출본을 **원래 폴더의 절대 경로**(`E:/github/고전 문학 게임/구운몽/design/source/`)에서 읽는다. worktree에서 돌려도 같은 파일과 견준다. 이 파일이 없는 기기에서는 15자 겹침 점검을 건너뛰었다고 찍고 통과한다.

**점검 시간과 일부만 돌리기**
- 전체는 10분 남짓 걸린다. 화면을 고치는 동안은 `ONLY=휴대폰 node check-content.mjs`처럼 이름 일부로 내용 점검의 화면 판 하나만 돌린다(정적 점검은 늘 돈다). 배경음은 `node check-bgm.mjs --no-lufs`로 음량 재기를 건너뛴다. 끝낼 때는 언제나 `node run-all.mjs` 전체.
- 각 점검은 127.0.0.1의 임의 포트에 자기 정적 서버를 띄우므로 여러 점검을 동시에 돌려도 포트가 부딪히지 않는다. 화면 캡처는 `tests/shots/`에 남는다(커밋 안 함).

**금지된 이름이 커밋 글에 들어갔다**
- 권리 점검은 `git log -p --all`로 모든 가지의 내용과 **커밋 글**까지 바이트로 찾는다. 이름이 한 번 커밋되면 파일을 고쳐도 실패가 남고, 이력을 다시 써야만 풀린다. 커밋하기 전에 스테이지한 파일과 커밋 글을 함께 확인하고, 커밋한 뒤 발견하면 더 커밋하지 말고 사용자에게 알린다.

## 原文 대조를 반영하는 절차

대조할 곳: 회목 16개와 핵심 구절 네 개. 근거로 쓸 수 있는 것은 국립중앙도서관 소장 계해본(1803, 을사본 번각, 청구기호 한古朝48-4)의 원문 이미지(전용 뷰어 설치 필요, 사용자 확인 사항) 또는 영인을 실은 학술서(『구운몽 자료 집성』 등)다. 위키문헌 전사본은 오자가 많고 깨어나는 대목이 빠져 있어 대조 근거가 아니다.

1. 영인과 한 글자씩 맞대어 `design/research/02_原文_대조기록.md`에 글자별로 남긴다. 의심 글자(峯/峰, 真/眞, 被/衾 등)는 영인이 보여 주는 대로만 정한다.
2. 데이터에서 그 회목을 `{ hoe, part, orig, gloss, src }`로 바꾸고 `status`를 지운다. `src`에 판본과 장을 적는다(예: 계해본(1803, 을사본 번각)).
3. **내용 점검을 같은 커밋에서 고친다.** 지금 `check-content.mjs`는 "데이터 어디에도 `orig`가 없고 회목은 모두 '대조 대기'"와 "걸음마다 原文 낙관이 화면에 없음"을 확인하므로 첫 原文이 들어가는 순간 실패한다. 대조 기록에 있는 글만 `orig`를 허용하도록 바꾼다.
4. 한자가 새로 생기면 `python tools/build_fonts.py`.
5. `node tests/run-all.mjs`. README의 '알려진 한계'에서 대조 대기 문구를 고친다.
