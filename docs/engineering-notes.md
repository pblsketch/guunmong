# 일하며 알게 된 것

## 필드 인물 그림과 화면

- 지도 안 NPC는 빈 테두리나 의자를 인물 대신 쓰지 않는다. 승인된 정지 전신 그림을 연결하고 인접 행동과 별도로 실제 그림의 HTTP 요청·표시를 검사한다.
- 2026-10-04 내장 image_gen으로 선녀·육관대사·유모 전신 후보를 만들고 사용자가 세 인물을 그대로 반영하도록 승인했다. 원본·실제 영어 ASCII 프롬프트·검토판은 assets/raw/rpg-npc-v1에 보존했다. tools/manifest_rpg_npcs_approved.json이 제품 세 파일의 승인 해시와 근거를 고정한다.
- 정지 NPC는 32px 한 프레임·한 행이고 발을 `(16,32)`에 맞췄다. 걷기 시트의 `(16,30)`과 다른 정지 그림 기본 앵커를 쓰므로 걷기 메타를 꾸며 넣지 않는다. 투명 픽셀 RGB도 0으로 정규화하여 31색+투명 이내로 만들며 후보 가공은 tools/process_rpg_npcs.py로 재현한다. 승인된 버전은 덮어쓰지 않는다.

## 글꼴

**새 글자가 다른 모양으로 보인다**
- 증상: 데이터나 화면 문구를 고친 뒤 몇 글자만 도트가 아니거나 명조가 아닌 글꼴(맑은 고딕, 바탕 등)로 보인다. 점검은 통과한다.
- 원인: `assets/fonts/`의 세 글꼴은 게임에 쓰인 글자만 남긴 부분 글꼴이다. 글꼴 파일이 없으면 404로 점검이 실패하지만, 파일 안에 글자 하나가 없는 것은 어느 점검도 보지 않는다. 브라우저는 조용히 CSS의 대체 글꼴로 내려간다.
- 대응: 글을 고칠 때마다 `python tools/build_fonts.py`를 돌리고 바뀐 woff2를 같은 커밋에 넣는다. 스크립트는 글자를 `js/**/*.js`, `index.html`, `manifest.webmanifest`에서만 모은다. CSS의 `content:` 글이나 README에 새 한글을 쓰면 모이지 않으므로, 화면에 보일 글은 JS나 데이터에 둔다.
- 확인: 스크립트가 글꼴마다 "글꼴에 없는 글자 N개"를 찍는다. 원본 글꼴에도 없는 글자가 생기면 그 글자를 바꾸거나 받아들인다.
- 학생이 결과 화면에 쓰는 이름은 미리 알 수 없으므로 부분 글꼴에 없는 글자가 대체 글꼴로 보이는 것이 정상이다(PNG도 마찬가지).

**'옛한글 글꼴'이라는 이름의 함정**
- CSS 주석과 파일 이름(`noto-serif-cjk-kr-old.woff2`, 글꼴 이름 GuunOld)은 옛한글 原文용처럼 보이지만, 실제로는 Noto Serif KR의 **한자**와 몇몇 문장부호만 담는다. 原文을 한문 회목·핵심 구절로 정했기 때문이다.
- 옛한글 자모(첫가끝·아래아)가 든 글을 原文으로 넣으면 `G.text`가 `old` 표시를 붙여 이 글꼴을 쓰게 하지만 자모가 없어 조합된 모양으로 나오지 않는다. 옛한글 原文을 쓰게 되면 옛한글 자모가 있는 원본 글꼴로 이 글꼴을 다시 만들어야 한다.

## 배경음

**`js/data/bgm.js`를 손으로 고친 것이 사라진다**
- 원인: `tools/make_bgm.py`는 곡 몇 개만 다시 만들 때도(`python tools/make_bgm.py calm lotus`) `bgm.js`를 통째로 다시 쓴다.
- 대응: 곡 배정, 악구, 합성 대체 곡(`synth`), 출처 문구는 스크립트의 `TRACKS`와 출처 문구 쪽을 고치고 다시 만든다.
- 다시 만들려면 원음 WAV(`tools/music_src/`, git 제외)와 ffmpeg가 이 기기에 있어야 한다. ffmpeg는 PATH 또는 `~/ffmpeg/bin/ffmpeg.exe`에서 찾는다.

**퉁소 곡이 실은 단소다**
- 국립국악원 「디지털 이음」 악구 목록에 퉁소가 없다(2026-10 확인). 난양공주의 달밤(`tungso`)과 취미궁(`chwimi`)은 같은 세로 대나무 관악기인 단소의 「청성곡」 악구로 만들었다. 출처 문구와 README에 "퉁소 대신 단소"가 있어야 하고, 내용 점검이 타이틀·설정의 출처 문구에서 이 표시를 본다. 퉁소 녹음을 구하기 전에는 이 문구를 지우지 않는다.

**음량 점검이 조용히 빠진다**
- check-bgm 단독 실행은 ffmpeg가 없으면 음량 검사를 생략할 수 있다. 전체 run-all은 ffmpeg를 먼저 찾아 없으면 실패한다. 완료 근거에는 곡별 LUFS·봉우리 측정 출력이 있어야 한다(-20 ±2, 봉우리 -0.5 dBTP 아래).

## 대사 목소리(0024)

- `python tools/make_tts.py`(장 번호를 주면 그 장만). 같은 글은 다시 만들지 않는다. 게임 전체를 돌면 지금 글에 없는 옛 소리와 목록 줄을 지운다.
- 파일 이름은 화면에 보이는 글(`text` 또는 `gloss`)의 FNV-1a 32비트 해시(UTF-16 단위)다. JS(`js/game/voice.js`)와 파이썬(`fnv`)이 같아야 한다. 글을 한 글자라도 고치면 그 줄은 소리가 없어지므로 다시 돌린다.
- 한국어 본문은 파이썬 `urllib`로 UTF-8을 보낸다. bash의 curl로 보내면 "invalid unicode code point"로 거부된다.
- 소리 파일(`assets/voice/*.mp3`)과 목록(`js/data/voice.js`)은 같은 커밋에 넣는다. 목록만 있고 파일이 없으면 학생 화면에서 404가 나고 점검이 실패한다. 새 목소리 모델을 쓰기 전에는 사용권을 사용자에게 확인한다.

## 그림 만들기(Codex)

**Codex가 요청한 크기를 무시한다**
- 증상: `-Size 1536x1024`를 주어도 1672×941 같은 다른 크기·비율로 나온다.
- 대응: 가공 단계는 생성 크기를 믿지 않는다. `pixlib.center_crop()`으로 목표 비율의 가운데를 자르고 면적 평균으로 줄인 뒤 32색으로 줄인다. 그래서 프롬프트에 "중요한 것은 그림 높이의 가운데 80% 안에"를 넣고, 집 그림은 잘릴 띠의 위치를 계산해 그 안에만 그리게 한다. 새 프롬프트도 가장자리가 잘린다고 보고 쓴다.

**`gen.ps1`이 몇 분씩 멈춘다**
- 원인: 전역 `~/.codex` 설정의 플러그인·MCP를 불러오느라 시작이 멈춘다.
- 대응: `gen.ps1`은 그림마다 `%TEMP%\codex-img-guun-<이름>`을 `CODEX_HOME`으로 삼아 모델·승인·샌드박스 세 줄짜리 `config.toml`과 `auth.json` 복사본만 둔다. 이 방식을 바꾸지 않는다. 대신 생성이 끝나면 이 폴더들을 지운다(자격 증명 복사본이 남는다).
- 프롬프트는 영어(ASCII)로만 쓴다. 명령 줄에 그대로 넣어 넘기므로 한글이 섞이면 깨진다(스크립트가 `WARN`을 찍는다). Codex에게 프롬프트 파일을 읽게 하면 샌드박스가 막으므로 내용을 명령에 넣는 방식을 유지한다.
- 참조 그림 모드: `same`(같은 인물, 표정만), `style`(화풍만), `char`(옷·머리 모양만 따르고 도트로 다시 그림), `cast`(옷은 따르되 얼굴은 프롬프트대로), `scene`(설정 그림 속 인물 가운데 **이름을 댄 사람만** 그림). 장면에 다른 인물이 끼어들면 `make_prompts.py`의 `ref#n`으로 필요한 인물만 잘라 만든 참조 묶음을 쓴다.

**배경을 빼면 옷이 뚫린다(크로마 키)**
- 투명 배경 그림은 단색 배경으로 생성해 색으로 뺀다. 기본은 마젠타(#FF00FF)다. 보라·분홍 옷이 든 그림(적경홍 초상 시트, 선녀 시트 b, 승상 옷의 말 `horse_walk_sang`)은 초록(#00FF00)으로 생성한다. 버들 초록 옷의 진채봉이 든 그림은 초록 키를 쓰면 안 된다.
- 키는 두 곳에서 맞아야 한다: 프롬프트를 만드는 `make_prompts.py`(`KEY_GREEN`)와 가공하는 `process_assets.py`·`process_sprites.py`의 시트 표. 한쪽만 바꾸면 배경이 남거나 옷이 사라진다.

**구슬처럼 아주 작은 그림**
- 16px 안팎의 구슬 세 장은 생성 그림을 줄이면 뭉개지므로 `process_assets.py`의 `beads()`가 직접 찍는다. 아주 작은 그림은 생성하지 말고 코드로 찍는다.

**말 스프라이트**
- 시트는 32×32 칸 6열×4줄(서 있기 2, 오른쪽 걷기 4, 뛰기 6, 위로 걷기 4), 발밑 기준점은 칸의 (16, 30)이다. 모든 프레임을 서 있기 첫 프레임의 키(28px)로 같은 배율로 줄이고 발을 기준점에 맞추어야 걸을 때 튀지 않는다. 가공 중 칸을 벗어난 프레임은 잘렸다고 찍힌다.

## 탑다운 후보 규격과 승인 기록

- `tools/manifest_topdown_v3.json`은 **미승인 후보 목록**이다. 제품 승인 메타와 혼동하지 않는다. `art approval pending`과 각 항목의 `unapproved`가 유지되는 동안 제품 `assets/`·`js/data/sprites.js`에 등록하지 않는다.
- `python tools/make_topdown_prompts.py`는 영어 ASCII·NOTEXT·TANG 프롬프트를 만든다. `python tools/generate_topdown_candidates.py`는 기존 `gen.ps1`만 창 없는 subprocess로 호출한다. 원본 존재·실제 종료 코드·임시 인증 복사본 제거를 확인하고 실패하면 멈춘다. 이미 있는 원본은 덮어쓰지 않는다.
- 첫 장소 후보는 돌다리·선방·화음현·취미궁이다. 3/4 탑다운 이동 공간을 새로 생성하며 기존 장면을 잘라 대신하지 않는다. 인물과 이동 가능한 가구는 배경에 넣지 않는다. 선방은 하나의 `map-cell` 후보를 처음·마지막에 공유하고 방석은 별도 가구 칸에서 그린다.
- 월드 칸은 32px, 장소 후보는 384×320(12×10칸)이다. 걷기 후보는 160×128(32px 셀 5열×4행), 발 기준은 `(16,30)`이다. 행은 아래·왼쪽·오른쪽·위, 각 행의 0번은 서기, 1~4번은 걷기다. 성진·양소유 선비복·양소유 승상복을 별도로 검토한다. 표정은 기존 큰 초상을 사용한다. **기존 지팡이 96px 셀은 변경하거나 축소하지 않는다.**
- 후보 목록의 `width/height`는 **전체 시트 파일** 크기다. 승인 뒤 제품 sprites의 `width/height`는 기존 규칙대로 **한 셀**인 32×32이며 `frames:5`, `rows:4`, `cell:{width:32,height:32}`, `anchor:{x:16,y:30}`과 네 방향을 함께 등록한다. 파일 크기 160×128을 셀 크기로 넘기지 않는다.
- 생성 모델이 좌우 행을 바꾸기도 한다. 원본을 직접 보고 `sourceDirections`에 실제 순서를 적고 가공 단계에서 목표 행 순서로 재배열한다. 프롬프트 이력을 고쳐 실제 생성 순서를 숨기지 않는다. 최종 32px 셀의 아래쪽 발 띠로 정렬해야 축소 전 인물의 발 띠와 차이가 생겨 2px 흔들리는 일을 막는다.
- 재사용 시트는 128×64, 4열×2행이다. 바닥 두 칸은 투명 여백 없이 32px를 채우며 벽·방석·탁자·의자·상자는 분리된 칸이다. `frameKeys`로 이름을 구분한다. 원본·팔레트·프레임의 상업 사용 전제는 기존 Codex 생성 규칙을 따른다.
- `python tools/process_topdown_candidates.py`는 `assets/raw/topdown-v3` 아래에만 후보·검토판을 만든다. 기존 후보가 다른 픽셀이면 덮어쓰지 않고 새 버전 이름을 요구한다. `--check`는 실제 크기·32색 이하·무손실 WebP·빈 프레임·잘림·발 기준·걷기 변화·메타 범위를 검사한다. 가공된 시트의 모든 프레임을 확인하고 원본 분할 경계의 겹침도 거부한다. 자동 검사는 시점·의상·배경 속 인물의 의미를 판별하지 못하므로 원본과 검토판을 함께 직접 본다.
- `review/contact-sheet-v1.png`는 실제 32px·2배·4배와 390px 장소 비교다. `review/animation-review-v1.html`은 후보만 재생하며 저장하지 않는다. `node tools/check_topdown_review.mjs`는 로컬 HTTP에서 320/390/820/1280px의 파일 요청·정수배·실제 픽셀 변화·멈춤·가장자리 접근·외부 요청 없음과 기존 96px 지팡이를 확인한다. 캡처·명령 출력은 `tests/shots/topdown-v3`에 둔다.
- 승인 전 결과는 **후보 검증**이며 학생 완주나 제품 자산 완료가 아니다. 승인 전달 뒤에만 승인 파일·해시·sprites 메타·제품 검사 규격을 함께 반영하고 `python tools/check_assets.py`, `node tests/check-assets.mjs`와 최종 전체 검사를 실행한다. 무시된 원본·후보·검토판 목록은 작업 폴더 정리 전에 원래 폴더로 보존한다.
- 2026-10-04 사용자가 검토판의 현재 후보 여덟 개를 승인했다. 승인 범위·검토판 해시·원본/프롬프트 해시·제품 해시는 `tools/manifest_topdown_approved.json`에 고정했다. `python tools/topdown_approved.py --install --require-sources`는 해당 바이트만 `assets/world/`에 복사하고 키트의 승인된 32px 칸 여덟 개를 픽셀 그대로 분리한다. 이전 후보는 포함하지 않는다. 이후 파일 교체·재생성·리디자인에는 새 승인이 필요하다.
- `python tools/check_assets.py --topdown-provenance`는 원본이 보존된 환경에서 원본까지 필수 검사한다. 일반 검사는 공개 사본에 원본이 없어도 승인된 제품 해시·크기·팔레트·프레임을 확인하며 원본이 있으면 대조한다. 현재 필수 그림은 기존 141개와 탑다운 16개(원본 바이트 복사 8개·키트 칸 분리 8개), 정지 NPC 3개, 여도사 걷기 1개, v4 43개(장소 14·선녀 7·NPC 14·물건 8)로 총 204개다. 157개는 탑다운만 반영했던 중간 단계의 수다.
- `node tools/check_topdown_products.mjs`는 실제 제품 경로·GUUN.sprites 메타로 320/390/820/1280px에서 HTTP 응답 해시·정수배·네 방향 서기/걷기 픽셀을 검사한다. `tests/check-assets.mjs`가 이 검사와 기존 UI 자산 관찰을 함께 실행한다. 이 제품 파일 관찰은 새 core/app·맵 자료와 연결된 학생 월드 조작을 검증한 것이 아니다. 연결된 본편의 학생 플레이는 check-content와 check-rpg에서 따로 검사한다.

## 화면

**모바일에서 드래그가 끊기거나 두 번째 손가락의 행동이 빠진다**
- ResizeObserver의 최초 알림은 실제 크기 변경이 아니다. 첫 폭·높이를 보관하고 달라질 때만 이동과 누름을 취소해야 화면 생성·오류 재시도 직후 첫 입력이 사라지지 않는다. 배치 갱신은 최초 알림에도 실행한다.
- 조이스틱으로 캡처를 옮길 때 자식의 lostpointercapture도 버블링한다. 실제 소유 요소 자신의 캡처 상실만 취소로 처리해야 한다.
- 첫 손가락을 계속 누르면 둘째 손가락에 click이 생기지 않을 수 있다. 행동 단추는 누른 포인터와 대상·행동을 보관하고 단추 안에서 뗄 때 한 번 실행한다. 키보드 click은 따로 유지하며 취소·이탈·회전·모달에서는 누름을 폐기한다.
- 행동 단추를 뗄 때 대화가 열리면 같은 터치의 호환 click이 새 대화창으로 전달될 수 있다. 단추의 누름이 끝나거나 취소되면 그 click도 소비해 첫 대사가 자동으로 넘어가지 않게 한다. 다음 새 pointerdown과 키보드 활성화는 허용한다.
- 드래그 뒤 호환 click은 새 pointerdown 전까지 막는다. 일정 시간만 막으면 늦은 click이 목적지 이동으로 이어질 수 있다. 다음 실제 탭·마우스 입력과 키보드 활성화는 유지한다.
- 실제 CDP touch로 연속 이동·방향 변경·두 손가락·벽·단순 탭·취소·저장 실패·이전 회차를 검사한다. NPC의 사각 테두리는 제거하고 작은 느낌표와 오른쪽 행동 단추로 다음 대상을 알린다.

**휴대폰에서 캐릭터가 너무 빨리 달린다**
- 원인: 한 칸 이동을 180ms로 고정했고 휴대폰은 한 칸이 64 CSS px(2배)라 초당 5.5칸, 390px 화면을 1초 남짓에 가로질렀다.
- 대응: world.js의 STEP_MS 260ms(초당 약 3.8칸), FRAME_MS 65ms(한 칸에 걷기 그림 4장)로 바꿨다. 속도를 바꾸면 화면 검사의 이동 대기 시간이 함께 늘어난다.

**가로 휴대폰에서 대화창이 왼쪽에 붙는다**
- 원인: style.css의 `.stage-story { max-width: 484px; margin: 0 auto }`가 월드 대화창에도 걸리고, rpg.css가 margin만 0으로 덮어 가운데 정렬이 풀렸다. 세로 390px에서는 폭이 484px보다 좁아 드러나지 않았다.
- 대응: `.world-dialogue`에 max-width:none을 두고, 높이 540px 이하 가로에서는 초상·글·다음 단추를 한 줄 띠로 놓는다. 생각 선택은 가로에서 나란히 놓는다.

**물건을 누르면 물건 이름이 화자로 찍힌다**
- 원인: stage.show가 대상 인물이 없는 경우(물건)도 '대상이 말하는 줄'로 판정해 물건 label을 화자 이름으로 썼다.
- 대응: label은 대상 인물이 직접 말하는 줄(say === targetPerson)에만 쓴다. 서술 줄은 이름 칸을 비운다.

**빌려 쓴 장소 그림 위에서 물·지붕을 걷는다**
- 원인: 남전산·하북은 돌다리, 춘운 정원·적생의 길은 화음현, 퉁소·잔치는 취미궁 그림을 쓰면서 walk를 바닥 방처럼 거의 전부 1로 두었다.
- 대응: 그림을 빌려 쓰는 지도는 원래 지도의 통행 칸을 따르고 대상·입구를 그 위로 옮겼다. 하북 궁정은 물가 다리 그림을 쓰지 않고 회색 바닥 방으로 바꿨다. 확인은 그림 위에 walk·대상·입구를 겹친 검토 그림으로 한다. 고유 그림이 없는 열네 지도는 바닥 무늬 방으로 남아 있다(findings 참조).

**처음 화면의 초록 배경이 제목과 메뉴를 덮는다**
- 원인: 메뉴 안에 절대 위치의 game-field를 넣어 제목·단추 위에 배경이 그려졌다. 배경의 pointer-events가 none이어서 자동 클릭은 아래 단추를 눌렀고, 클릭 성공만으로는 가림을 발견하지 못했다.
- 대응: 메뉴에서는 배경과 메뉴 창을 형제로 두고 메뉴 창을 위에 쌓는다. 월드·활동 화면의 기존 필드 구조는 유지한다. 변경한 app과 RPG CSS 주소에 버전을 붙여 이전 캐시와 섞이지 않게 한다.
- 확인: 모바일 가로/세로 네 크기와 일반/큰 글자에서 첫 화면·제목·시작/이어 하기의 실제 캡처 색상, 터치, 목차/설정, 게임에서 돌아온 메뉴를 검사한다. 같은 검사에 이전 app/CSS를 제공하면 가림으로 실패해야 한다.

**조사가 '을(를)'로 찍힌다**
- 앞말이 데이터에서 오는 문장은 `G.util.josa(낱말, '을/를')`로 조사를 고른다. 이 함수는 마지막 한글 글자의 받침을 보고, 닫는 문장부호·따옴표·괄호(괄호 안 한자 포함)는 건너뛰고, 숫자는 읽는 소리로 보며, ㄹ 받침 뒤에는 '으로'가 아니라 '로'를 고른다. 해석 글처럼 「」로 감싼 말에 붙일 때는 「」를 포함한 글을 넘긴다.

**알림이 글이나 단추를 가린다**
- `G.ui.toast()`는 위 막대(`.topbar`)의 빈 곳(장면 이름 글자 끝과 오른쪽 단추 사이)에 작은 띠로 뜨고, 자리가 모자라면(휴대폰) 위 막대 전체를 덮었다가 누르면 닫힌다. 위 막대가 없는 화면에서는 화면 맨 위에 뜬다. 알림을 본문 위나 아래 판 근처에 새로 띄우면 내용 점검의 알림 위치 재기가 실패한다.

**흐린 글씨 명암비**
- `--ink-3: #6a5a47`은 한지 바탕(`--paper`)에서 명암비 4.5를 넘기려고 고른 값이다. 이보다 밝은 회갈색이나 투명도를 쓴 글씨는 내용 점검의 명암비 재기에서 걸린다. 그림이 바탕인 곳은 재지 않는다.

**좁은 휴대폰에서 장면 그림이 화면보다 작다**
- 대사창 무대는 정수배 그림을 가운데서 잘라 보여 준다. 전체 그림 보기에서는 역정수배로 줄어 화면 폭보다 작을 수 있다. 둘 다 보간으로 폭을 억지로 맞추지 않는다. 가장자리나 대사창 뒤의 구슬은 원래 좌표를 유지한 채 그림 살피기에서 찾게 하고, 320/390px 실제 클릭으로 확인한다.

**뒤로 가기로 깨어나기 전 화면이 되살아난다**
- 브라우저가 예전 화면을 캐시(bfcache)에서 그대로 되살리면 스크립트가 다시 돌지 않는다. `app.boot()`가 `pageshow`의 `persisted`에서 저장소를 다시 읽고 지금 화면을 다시 판단한다. 새 화면 모듈이 자기 상태를 따로 들고 있다면 같은 때에 다시 그려야 한다.

## 저장

**저장 모양을 바꿀 때**
- v3 load는 허용된 맨 위 열쇠·자료형을 읽고 기본 객체와 저장 값을 얕게 합친다. v2·v1은 고치거나 지우지 않는다(v3가 없을 때 v2에서 설정 넷만 읽음). journal/interp/play 안쪽 구조가 바뀌면 기존 v3 기록을 별도로 시험해야 하며, 자동으로 임의 깊이까지 변환된다고 가정하지 않는다.
- `fresh().pos`는 null이라 `typeof`로만 자료형을 비교하면 객체·배열 `pos`가 통과한다. `pos`는 null·문자열만 받는다.
- 0022에서 새 열쇠로 모두 새로 시작하게 한 까닭: 옛 판의 능력·재화·등급 호환 경로가 새 선택·첫 판가름 기록과 섞이면 막대·되짚기의 뜻이 흐려진다. 다음 저장 모양 변경 때도 "이어 하기"와 "새로 시작"을 사용자에게 먼저 묻는다.

**선택과 첫 판가름을 저장할 때**
- 생각 선택 자리에서 행동을 먼저 저장하고 대화 뒤에 선택을 따로 저장하면, 그 사이 새로 고침으로 선택이 빈 채 행동만 남는다. 행동과 선택은 `applyExperience({choice})` 한 번으로 저장하고, 선택 전에는 행동을 저장하지 않는다.
- search 첫 판은 촛불이 다 꺼질 때 판가름이 나므로, 헛짚은 곳을 누를 때마다 `tried`로 저장해야 새로 고침으로 첫 판을 되돌리지 못한다.
- 선생님용·바로가기 기록을 학생의 선택으로 남기면 되짚기와 결과가 학생의 것이 아니게 된다. 규칙상 기록 안 함(teacher/auto/awake/decided/duplicate)은 오류가 아니라 반응만 보이고 진행한다.
- 장면 id를 바꾸면 그 id를 가리키던 `pos`·`done`이 허공을 가리킨다. `pos`를 못 찾으면 이어 하기가 첫 장면으로 간다.

**다시 연 장면이 기록을 바꾼다**
- 새 걸음이나 화면을 만들 때 `ctx.readonly`(마친 장면 다시 열기)를 보지 않고 상태에 쓰면, 학생이 목차로 마친 장면을 다시 열기만 해도 장부·집·구슬이 바뀐다. 쓰기 전에 ctx.readonly와 현재 권한·회차·생존을 확인하고 저장 API에도 같은 run/readonly를 넘긴다. 화면의 readonly 검사만으로 reader나 오래된 콜백을 막았다고 판단하지 않는다. 꿈 일지·해석처럼 한 번 정한 뒤 잠기는 화면은 `final`·`heard` 같은 자기 표시도 함께 본다.

**3장 이어 하기**
- 깨어나기 전에 3장에서 끄면 취미궁부터 연출을 다시 보지만 기존 done·수행자·auto·부분 행동은 지우지 않는다. 마친 안내는 읽기 전용으로 재연하고 다음 표시 위치만 옮긴다. 교사 미리보기로 남은 선방 이후의 위치도 학생으로 돌아오면 취미궁부터 재연한다. 지팡이는 예외적으로 실제 타격 입력을 기다리며 옛 auto staff의 teacher 힌트와 다른 auto는 유지한 채 commitWake에서만 실제 완료·깨어남·선방 위치를 원자 확정한다.

## 점검

**작업 가지 폴더(worktree)에서 점검이 시작도 못 한다**
- 증상: `node tests/check-*.mjs`가 `Cannot find package 'playwright'`로 끝난다.
- 원인: `tests/node_modules`는 git이 빼므로 새 worktree에는 없다.
- 대응: 원래 폴더의 것을 Windows 연결점(junction)으로 잇는다. 관리자 권한이 필요 없다.
  `cmd /c mklink /J tests\node_modules "E:\github\고전 문학 게임\구운몽\tests\node_modules"` (worktree 맨 위에서)
- 본문 대조는 원래 폴더의 절대 경로 E:/github/고전 문학 게임/구운몽/design/source/를 사용한다. check-rights 단독은 파일 부재 시 대조를 생략하지만 check-data는 실패하므로 전체 완료는 불가하다. 자료를 저장소에 복사해 해결하지 않는다.

**검사 도중 제품을 고치면 엉뚱한 실패가 난다**
- 화면 검사는 실행 중에도 제품 파일을 HTTP로 새로 읽지만, 검사 도우미 모듈은 시작할 때 한 번 읽는다. 실행 중에 속성 이름(data-*)이나 데이터를 바꾸면 도우미와 제품이 어긋나 시간 초과로 실패한다. 이야기 총량을 잠시 넘긴 데이터도 시작을 막아 같은 증상을 낸다. 검사가 끝난 뒤 고치고 다시 돌린다.

**대표 시험 자료가 제품 자료와 달라진다**
- tests/fixtures의 rpg-opening/rpg-front/rpg-waking.js는 제품 데이터의 사본이며 도입 관찰 검사가 지도 등을 제품과 비교한다. 지도·대상·도전을 바꾸면 `node fixtures/rpg-opening-build.mjs`, `rpg-front-build.mjs`, `rpg-waking-build.mjs`로 다시 만든다. 빌드는 사본에 있는 장면의 도전만 남긴다.

**점검 시간과 일부만 돌리기**
- 개발 중에는 관련 check 파일을 직접 실행한다. 현재 check-content는 관찰 회귀·출처·파일 열기·세 판을 모두 실행하고 판별 ONLY 선택을 제공하지 않는다. run-all은 ONLY나 생략 인자를 거부한다. 개별 bgm의 --no-lufs는 완료 근거가 아니며, 마지막에는 월드를 포함한 열 검사를 모두 실행한다.
- 각 점검은 127.0.0.1의 임의 포트에 자기 정적 서버를 띄우므로 여러 점검을 동시에 돌려도 포트가 부딪히지 않는다. 화면 캡처는 `tests/shots/`에 남는다(커밋 안 함).

**금지된 이름이 커밋 글에 들어갔다**
- 권리 점검은 `git log -p --all`로 모든 가지의 내용과 **커밋 글**까지 바이트로 찾는다. 이름이 한 번 커밋되면 파일을 고쳐도 실패가 남고, 이력을 다시 써야만 풀린다. 커밋하기 전에 스테이지한 파일과 커밋 글을 함께 확인하고, 커밋한 뒤 발견하면 더 커밋하지 말고 사용자에게 알린다.

## 구판 육성 화면에서 얻은 동작 그림 지식

준비 화면은 현재 실행 경로에 없다. 아래는 보존 자산의 가공 이력과 현행 지팡이에도 적용되는 시트 제어 지식이다.

**32px 동작을 키워도 얼굴과 손이 돌아오지 않는다**
- 증상: 준비 동작을 화면에 약 96px로 보이게 해도 얼굴·손·책이 뭉개졌다.
- 원인: 32px 칸에서 인물 높이가 약 28px로 줄어든 뒤 다시 확대되어, 원본의 정보가 이미 사라졌다.
- 대응: 2026-10-03 같은 원본의 32/64/96 비교를 보고 사용자가 96px를 선택했다. 준비 네 동작과 지팡이는 96px 셀을 쓰고 말판 말 32px·아이콘 32px와 구별한다. 원본·이전 후보를 보존하고 실제 표시 크기에서도 확인한다.

**시트가 등록돼도 자동 재생되지 않는다**
- 증상: 후보 미리보기는 움직이는데 실제 준비 화면의 배경 위치가 고정됐다.
- 원인: 요소 생성의 style 객체에 넣은 --frames/--sheet-end가 실제 CSS 속성으로 등록되지 않았다.
- 대응: element.style.setProperty로 기록한다. 후보를 브라우저 메모리에서 보정해 통과시키지 말고 제품 코드 그대로 여러 시점의 배경 위치가 바뀌는지 검사한다.

**호승이 단추를 누르기 전에 난간을 친다**
- 원인: 컷신 진행만 멈춰도 CSS 시트 재생은 계속되므로 마지막 타격 프레임까지 순환한다. 얼굴 대체 그림으로만 시험하면 발견하지 못한다.
- 대응: staff 대기에서 stage.setSpriteFrame으로 0기준 2번에 고정한다. 클릭 동기 저장 뒤 3번 자세를 잠깐 보인 후 부서진다. 두 재생 주기 이상 대기·타격 중 재접속·readonly 전체 상태를 실제 시트로 확인한다.

**자동 준비 사건이 계속 반복된다**
- 증상: 앞 사건을 일부 준비한 뒤 선생님용으로 뒤 사건을 열고 다시 순차 진행하면, 자동 기록이 있는 사건에서 제자리로 돌아갔다.
- 원인: 자동 등급 때문에 다시 보기로 판정했으나 저장된 재개 위치도 같은 사건이었다.
- 대응: 현재 경로의 자동 기록은 autoAdvance로 구분해 내용·능력·보상·done·장부를 보존하고 다음 위치만 저장한다. 직접 다시 보기는 원래 위치로 돌아간다. 부분 준비 → 뒤로 바로가기 → 앞 사건 완료 → 자동 기록 재진입을 검사한다.

## 선생님용 전환과 현재 권한

- 증상: 깨어난 뒤 선생님용을 끄면 이전 HUD·인연 단추·열린 꿈 탭이 남았고, 잠긴 꿈 장면은 설정판을 닫을 때까지 유지됐다.

## 로딩 중 화면 검사

아래 말판 사례는 구판에서 발견한 검사 시점 문제다. 현재 월드 그림에서도 조건 선택과 표시 관찰을 같은 동기 구간에서 수행한다.

**정상 말판이 미준비 노출로 실패한다**
- 증상: 숨겨진 그림을 선택한 뒤 31.6ms 사이에 로딩이 완료되어, 검사에서는 부모 has-img·display:block·320px를 보면서도 실패했다.

- 대응: 상태 조건 선택과 computed style 읽기를 한 page.evaluate의 동기 실행에서 끝낸다. 지연 로딩의 정상 전환, 진짜 미준비 강제 노출, 캐시 재사용을 함께 검증한다. 기다리는 시간을 늘리거나 해당 단정을 삭제해서 덮지 않는다.
- 제품 쪽은 배율을 정하기 전 board-img를 숨기고, 치수를 설정한 뒤 has-img를 붙여 표시한다. 검사와 제품의 책임을 구분한다.

## 휴대폰에서 긴 글과 진행 단추

- 구판에서는 긴 카드가 그림 위에서 잘려 그림 아래로 글을 펼치고 문서 전체를 스크롤하게 했다. 그때의 점수 띠 sticky 처리는 구판 화면에 한정된다.
- 현재는 필드가 게임 화면을 채우며 대화는 임시 창, 소원·일지·해석·결과는 게임 안 책 창이다. 긴 내용은 창 안에서 스크롤하고 진행 단추·키보드 초점·터치 접근을 확인한다. 지도 아래 문서를 다시 붙이지 않는다.
- 390×844와 844×390 각각 일반·큰 글자로 도입·소원·지팡이·일지·해석·결과·PNG를 확인했다. 세로는 읽기 높이의 여유가 커 기본으로 유지하며 가로도 지원하고 강제 방향 잠금은 없다. Chrome 크기 검증을 실기기·실제 학생 선호로 확대하지 않는다.
- 조신설화는 결과에서 선택하는 비교 읽기다. id와 장 인덱스를 보존하며 옛 서장 pos·주소는 현재 허용 위치로 잇는다.

**첫 줄이 바로 넘어간다(실기기 지적)**
- 증상: NPC·물건 행동을 누르면 대사 첫 줄이 보이자마자 넘어가는 것 같다는 실기기 지적. Chrome 흉내(CDP 터치·행동 단추·NPC 탭·키보드, 가로/세로)와 MutationObserver 기록으로는 줄 순서가 기대와 같아 재현되지 않았다.
- 가정한 원인: 실기기 브라우저가 터치의 호환 click을 늦게 보내면, 행동 단추를 누른 그 누름이 막 뜬 첫 줄의 '다음'으로 도착한다.
- 대응: `G.util.staleTap(e, shownAt)`. 문서 전체의 pointerdown 시각을 캡처 단계에서 기록하고, 줄이 뜬 뒤 새 pointerdown이 없는 detail ≥ 1 click을 무시한다. 대화(world.js), 무대(stage.js), 진행 단추(app.js ctx.next), 컷신(cutscene.js)에 같은 규칙을 쓴다. 키보드 click(detail 0)은 통과한다. 고정 시간 지연은 빠른 학생의 의도한 누름까지 막아 쓰지 않았다.
- 검사: 도전 검사의 '늦게 도착한 탭'이 pointerdown 없는 detail 1 click을 보내 첫 줄이 남는지, 실제 누름과 Enter가 넘기는지 본다. 실기기 확인은 아직 하지 않았다.

**가로 휴대폰에서 긴 노트가 '다음'을 밀어낸다**
- 원인: 844×390에서 노트가 붙은 줄은 대화 상자 안 스크롤 아래로 단추 줄이 밀렸다.
- 대응: 가로 대화의 단추 줄을 `position: sticky; bottom: 0`으로 붙였다. 도전 검사의 '가로 휴대폰'이 첫 대화의 모든 줄에서 단추 가운데 점이 단추 자신을 가리키는지 본다.

**구슬 흔적이 가구로 보인다**
- 원인: 지도 데이터의 구슬 대상이 바닥·의자·방석 sprite를 쓰고 있었다. 월드는 sprite가 있으면 그 그림을 그린다.

## 학습 저장과 결과 내보내기

**일부 오답 저장 뒤 재시도하면 첫 기록이 중복된다**

- 확인: 첫 쓰기·부분 쓰기 실패, 재시도, reader·이전 run·교사 도움·확정 뒤 입력을 check-chapters에서 검사한다.

**화면의 이름과 PNG가 다르거나 초기화 뒤 다운로드가 도착한다**
- 원인: 이름 저장 실패를 무시하거나 그림·글꼴·Blob을 기다린 뒤 현재 모델을 다시 읽으면 버튼을 누른 때와 다른 결과가 나온다.
- 대응: 화면의 미저장 이름을 먼저 저장하고 클릭 시점 모델을 고정한다. 대기 뒤와 Blob 콜백에서 원래 run과 화면 생존을 다시 확인한다. 취소하면 다운로드 URL도 정리한다.
- 확인: DOM/PNG 대비 그림·선택 근거·이름 일치, 긴 이름, 이름 재저장 실패/복구, 대기 중 이탈·초기화를 실제 다운로드와 음성 회귀로 확인한다.
