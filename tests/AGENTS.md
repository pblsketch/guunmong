## 경계와 증거

- 제품 동작을 검사 코드로 흉내 내 통과시키지 않는다. 실제 버그는 제품을 고치고 판정이 잘못됐으면 그 원인을 재현해 고친다.
- 완주 세 판은 휴대폰 모두 적중, 태블릿 모두 빗나감, PC 혼합이다. 선생님용이나 진행 상태 주입으로 건너뛰지 않는다. 읽기 관찰과 접근 차단 시험은 가능하다.
- 통과는 실제 단정 결과와 종료 코드로 남긴다. 알림·그림·다운로드 대상이 하나도 없는데 빈 배열이라는 이유로 통과시키지 않는다.
- 로딩 전 숨김과 로딩 후 정수배 표시를 구분한다. 상태 술어가 든 요소 선택과 CSS 판정은 같은 page.evaluate 동기 구간에서 관찰한다. 진짜 미준비 노출을 검출하는 음성 회귀를 유지한다.
- 그림 파일은 HTTP 서버로 관찰한다. file 테스트는 파일 열기 기능 자체의 검증이며 일반 화면 캡처는 로컬 HTTP를 사용한다.
- 각 화면 검사는 127.0.0.1 임의 포트, 설치된 Chrome을 사용한다. 의도적인 fixture 누락 이외 자산 404와 바깥 요청은 실패다.
- PNG는 실제 다운로드·서명·구조·색/글 픽셀·그린 내용까지 확인한다. DOM에 저장 단추가 있다는 것만으로 통과시키지 않는다.
- shots와 node_modules는 커밋하지 않는다. 금지된 이름은 코드에서도 글자 번호 등으로 다룬다. 새 파일을 스테이지한 뒤 권리 검사를 실행한다.

## 실행 조건

Node 20 이상, tests의 Playwright, 설치된 Chrome, Python 자산 검사 의존성, ffmpeg가 필요하다. 설치는 사용자 확인 뒤 한다. 다른 작업 폴더에서는 tests/node_modules를 원래 폴더의 의존성에 연결할 수 있으나 원본을 삭제하지 않는다.

교과서 대조 파일은 원래 저장소 design/source의 절대 경로를 사용한다. check-data는 파일이 없으면 실패한다. check-rights 단독 실행은 이 대조가 생략될 수 있으므로 전체 결과와 혼동하지 않는다.

- 전체: node tests/run-all.mjs. ONLY 또는 생략 인자를 주지 않는다. ffmpeg가 없으면 시작 단계에서 실패한다.
- 부분: node tests/check-이름.mjs. check-content는 출처·파일 열기·세 판·관찰 회귀를 모두 실행한다.
- 개별 음량 생략: check-bgm의 --no-lufs는 개발 중에만 사용하며 완료 근거로 삼지 않는다. FFMPEG는 도구 경로를 지정한다.

새 검사는 run-all의 명시 목록에 연결한다. 형식·상태·타이밍을 바꾸면 관련 실제·임시 자료 검사와 부정 사례를 함께 유지한다. 처음부터 지나가는 검사만 만들지 말고 실제 실패를 잡는지 확인한다.
